# 莞客松 Skill 共创库内部操作手册

## 仓库定位

本仓库是莞客松团队用于收集、整理、审核和发布 AI 实践经验的内部知识库，暂不面向外部成员开放自行投稿。

外部成员、活动参与者和社群用户可以提供原始素材，但不需要操作 GitHub。由团队统一完成筛选、标准化、代投稿和审核。

```text
素材收集 → 内部整理 → 统一代投稿 → 自动生成 Skill → 内部审核 → 合并入库 → 对外展示
```

## 角色分工

### 素材提供者

提供 Prompt、工具玩法、AI 信息差、专业工作流或创意案例，不负责 GitHub 操作。

### 素材收集人

将活动、围炉会、群聊、问卷和项目中的零散素材录入统一表格或文档。

### 内容整理人

负责判断是否值得入库、选择分类、去重、改写步骤、提炼 Prompt、补充适用场景，并检查隐私、版权、安全和公开风险。

### 代投稿人

由拥有仓库写入权限的内部成员提交 Issue 或本地 Skill 包。Issue 自动化只接受具有 `write`、`maintain` 或 `admin` 权限的提交者。

### 审核人与管理员

检查文件结构、内容质量、署名与来源、风险、索引和 CI，最终合并 PR 并检查展示页。

## 素材收集表

建议字段：

```text
编号
收集日期
素材标题
素材分类
素材来源
原始提供者
适用场景
原始内容
整理后步骤
Prompt 示例
案例效果
风险备注
整理负责人
当前状态
对应 GitHub Issue
对应 Pull Request
是否已合并
```

推荐状态：

```text
待整理 → 整理中 → 待代投稿 → 已代投稿 → 待审核 → 需修改 → 已合并
```

不适合收录时标记为 `暂不收录`。

## 入库标准

优先收录：

1. 有明确使用场景。
2. 有可执行步骤或可复制 Prompt。
3. 有实际效果或可信案例。
4. 能被他人复用。
5. 适合公开展示。
6. 符合莞客松青年 AI 应用实践定位。

暂不收录：

1. 只有一句想法，没有步骤。
2. 纯聊天记录或无法复现的个人经验。
3. 依赖个人隐私、内部机密或未授权数据。
4. 涉及违规、灰产或明显安全风险。
5. 与已有 Skill 高度重复。
6. 大段搬运网络原文。

## 内部代投稿流程

1. 在统一素材表中完成初筛和整理。
2. 进入 `Issues → New issue → 内部 Skill 代投稿`。
3. 填写原始提供者、素材来源和整理人，确认内容适合公开。
4. 等待 `Skill submission to PR` Action 自动生成 Draft PR。
5. 按 [审核指南](review-guide.md) 检查内容并完成必要修改。
6. 将可发布 Skill 的 `skill.json.status` 设为 `reviewed`。
7. 确认 `Validate repository / validate` 通过后合并。
8. 检查 `index/skills.json` 和 GitHub Pages 展示页。

## 署名规则

- 单人原创：`author` 填原始作者，`curator` 填莞客松整理人。
- 多人共创：`author` 可填“莞客松围炉会共创”。
- 团队方法论：`author` 填“莞客松团队”。
- 网络公开案例：`author` 填“公开资料整理”，并在 `source` 中提供来源说明。

不得把代投稿人的 GitHub 用户名误写成原始作者。`github` 字段用于记录仓库操作或可确认的作者账号，无法确认时可以留空。

## 推荐节奏

常规运营：

```text
周一至周五收集素材 → 周六集中整理 → 周日统一代投稿和审核
```

活动运营：

```text
活动前准备收集表
活动后 24 小时内整理第一批素材
活动后 3 天内完成代投稿
活动后 7 天内完成审核合并
```

仓库达到 20 至 30 个稳定、高质量 Skill 后，再评估是否开放外部自行投稿。
